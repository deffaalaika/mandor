# mandor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Skill Claude Code global `/mandor` yang membuat Claude jadi lead engineer: menulis plan super-detail di luar repo project untuk dieksekusi model lokal step-per-step, lalu memverifikasi seluruh commit di akhir, plus installer tanpa login GitHub.

**Architecture:** Instruksi perilaku di `skills/mandor/SKILL.md` + `references/`. Bagian yang bisa dicek secara deterministik dipindah ke script Python stdlib di `skills/mandor/scripts/`: validator format plan (`check_plan.py`), pemeriksa commit terhadap plan (`check_commits.py`), dan hook penjaga (`guard.py`) yang memblokir Claude menulis ke repo project atau mengubah state git. Format plan didefinisikan ketat di `references/plan-format.md` supaya bisa di-parse script. Distribusi: `build-release.sh` → zip + `SHA256SUMS` di GitHub Release, `get-mandor.sh` + `install.sh` (pola `claude-portable`).

**Tech Stack:** Markdown (SKILL.md), Python 3.9+ stdlib only (scripts + `unittest`), bash 3.2-compatible (macOS default) untuk installer, git.

**Spec:** `docs/design.md`

## Global Constraints

- Repo: `~/mandor`, nanti public `deffaalaika/mandor`. **Tidak ada commit, `gh repo create`, push, atau Release tanpa perintah eksplisit user.** Setiap task berakhir di titik stop, bukan commit.
- Saat user menyuruh commit: set identitas lokal repo dulu: `git config user.name "Deffa Alaika"` dan `git config user.email "89124623+deffaalaika@users.noreply.github.com"` (global config tidak diubah). **Nol atribusi AI** di pesan commit (tanpa `Co-Authored-By`, link session, "Generated with").
- Script: Python 3.9+, stdlib saja, tanpa dependency pip. Shell: kompatibel bash 3.2 (tanpa associative array, tanpa `mapfile`), `set -euo pipefail`.
- Skill ter-install di `~/.claude/skills/mandor/`. Tidak ada file yang ditulis ke repo project user, kapan pun.
- Folder plan selalu **di luar** repo project, path ditanyakan ke user setiap kali.
- Budget token per step: `BUDGET = 16000`, peringatan di `WARN_AT = 12000`. Estimasi: `ceil(jumlah karakter / 4)`.
- Maksimal file di `FILES TO CHANGE` per step: 2. Maksimal step per plan: 10 (lebih → WARN, Claude minta user memecah task).
- Bahasa: SKILL.md, README, references untuk Claude, dan README folder plan dalam **bahasa Indonesia**. Isi step yang dibaca model lokal (blok aturan + step) dalam **bahasa Inggris**.
- Pesan commit di repo project: sepenuhnya keputusan user. Tidak ada template; pencocokan commit↔step berdasarkan urutan.

## Review Focus

- Path folder plan berisi spasi atau diawali `~` → script harus `expanduser()` + `resolve()` dan tetap benar. (Test di Task 2.)
- Base SHA bukan ancestor `HEAD` (user merge/rebase dari main di tengah run) → `check_commits.py` FAIL dengan pesan jelas, bukan hasil palsu. (Test di Task 3.)
- File hasil commit beda dari plan hanya karena CRLF / spasi akhir baris / newline akhir file → WARN, bukan FAIL. (Test di Task 3.)
- Perintah git yang dibungkus: `cd app && git commit ...`, `git -C /x push`, `git -c a=b reset` → diblokir guard; `git status/log/diff/show/rev-parse` tetap boleh. (Test di Task 4.)
- Isi kode berbahasa Indonesia / karakter non-ASCII di file Kotlin → baca/tulis selalu UTF-8. (Test di Task 2.)

Kontrak format yang dipakai Claude (menulis), model lokal (membaca), dan script (memvalidasi).

**Format yang dikunci (ditulis di `plan-format.md`):**

`meta` (satu `key=value` per baris, tanpa kutip): `repo` (path absolut repo project), `base` (SHA lengkap), `steps` (int), `revision` (int, mulai 1), `status` (`writing` | `ready`), `created` (YYYY-MM-DD), `task` (satu baris ringkasan).

`step-N.md`:
```
<!-- mandor step=N -->
# Step N: <title>

## EXECUTOR RULES
<isi executor-rules.md, verbatim>

## GOAL
## FILES TO CHANGE
- CREATE <path> (FULL FILE)
- MODIFY <path> (ANCHOR EDIT)
- MODIFY <path> (FULL FILE)
- DELETE <path>
## FILES TO READ
- <path>:<start>-<end>        (atau satu baris "- none")
## CHANGES
FILE: <path>
<<<<<<< SEARCH
<teks lama persis, harus unik di file>
=======
<teks baru>
>>>>>>> REPLACE

FILE: <path>
<<<<<<< FULL FILE
<isi file utuh>
>>>>>>> END
## FORBIDDEN
## DONE WHEN
```
Section wajib, urutan tetap: `EXECUTOR RULES, GOAL, FILES TO CHANGE, FILES TO READ, CHANGES, FORBIDDEN, DONE WHEN`. Path relatif terhadap root repo project. `CREATE` wajib `(FULL FILE)`.

`executor-rules.md`: blok aturan bahasa Inggris dari design §6 (kerjakan hanya step ini, baca hanya file yang disebut, dilarang git/Gradle/adb/terminal, dilarang file di luar daftar, dilarang dependency baru / ubah test lama / `@Ignore` / TODO / stub / refactor, terapkan kode apa adanya, SEARCH tidak cocok persis atau ragu → stop dan tulis `QUESTION: <...>`, selesai → daftar file yang diubah tanpa klaim test lolos). Termasuk instruksi cara menerapkan blok `SEARCH/REPLACE` dan `FULL FILE`.

`plan-readme-template.md` (ID): placeholder `{{PLAN_DIR}}`, `{{STEPS}}`, `{{STEP_LIST}}`; isi: per step `pbcopy < "{{PLAN_DIR}}/step-N.md"` lalu paste ke sesi Agent Mode baru; tolak permintaan terminal dari Agent Mode; commit manual (pesan bebas); jangan merge/rebase dari main dan jangan push sebelum `/mandor verify` lolos; kalau model menulis `QUESTION:`, jalankan `/mandor question <N> <teks>`.

**Interfaces:**
- Produces (`mandor_plan.py`):
  - `SECTIONS: list[str]` (7 nama di atas), `BUDGET = 16000`, `WARN_AT = 12000`, `MAX_FILES_PER_STEP = 2`, `MAX_STEPS = 10`
  - `read_meta(plan_dir: Path) -> dict[str, str]`
  - `@dataclass FileChange(action: str, path: str, mode: str | None)` (`mode` None untuk DELETE)
  - `@dataclass ReadRef(path: str, start: int, end: int)`
  - `@dataclass Block(path: str, kind: str, search: str | None, text: str)` (`kind` ∈ `"SEARCH"`, `"FULL"`)
  - `@dataclass Step(number: int, title: str, sections: dict[str, str], changes: list[FileChange], reads: list[ReadRef], blocks: list[Block], errors: list[str])`. Error parsing dikumpulkan di `errors`, tidak raise.
  - `parse_step(path: Path) -> Step`
  - `rules_block(skill_dir: Path) -> str` (isi `references/executor-rules.md`, di-strip)
  - `apply_blocks(content: str | None, blocks: list[Block]) -> tuple[str | None, list[str]]`: terapkan berurutan; SEARCH harus muncul tepat 1x di konten saat itu, kalau tidak error `"SEARCH block not unique in <path> (found N)"` dan blok dilewati; FULL mengganti isi.

### Task 2: `check_plan.py`, validator plan

Claude wajib menjalankan ini setelah menulis/merevisi plan dan memperbaiki plan sampai `RESULT: PASS`.

**Files:**
- Create: `skills/mandor/scripts/check_plan.py`
- Test: `tests/test_check_plan.py`, `tests/helpers.py` (bikin repo git sementara + folder plan sementara)

**Interfaces:**
- Consumes: semua dari `mandor_plan.py`.
- Produces: CLI `python3 check_plan.py <plan-dir>`. Repo diambil dari `meta.repo`. Output per baris: `INFO|WARN|FAIL [step N: ]<pesan>`, baris terakhir `RESULT: PASS` atau `RESULT: FAIL (<n> failures)`. Exit 0 kalau PASS, 1 kalau FAIL, 2 kalau error pemakaian.
- Produces: `tests/helpers.py`: `make_repo(files: dict[str, str]) -> tuple[Path, str]` (repo + SHA commit awal), `make_plan(meta: dict, steps: dict[int, str]) -> Path`, `step_text(n, title, changes, reads, blocks, rules) -> str`.

**Aturan cek:**
1. `meta` punya semua key; `status` valid. Kalau tidak → FAIL.
2. Folder plan (resolve + expanduser) berada di dalam `meta.repo` → FAIL `"plan folder is inside the project repo"`.
3. `status=ready`: `step-1..step-<steps>` ada lengkap, tidak ada step ekstra. `status=writing`: hanya cek step yang ada, plus WARN `"plan incomplete"`. `steps > 10` → WARN.
4. Per step: `errors` dari `parse_step` → FAIL; isi `EXECUTOR RULES` ≠ `rules_block()` → FAIL `"executor rules block modified"`; `FILES TO CHANGE` kosong atau > 2 → FAIL; tiap CREATE/MODIFY punya blok yang sesuai mode; tiap blok `FILE:` ada di daftar.
5. Simulasi berurutan mulai dari `git_show(repo, base, path)`: MODIFY/DELETE file yang tidak ada → FAIL; CREATE file yang sudah ada → FAIL; error `apply_blocks` (anchor 0x/2x+) → FAIL dengan nomor step.
6. `FILES TO READ`: file harus ada di simulasi saat itu dan `end <= jumlah baris`.
7. Token = `estimate_tokens(isi step + rentang FILES TO READ + isi saat ini tiap file MODIFY)`. `> BUDGET` → FAIL; `> WARN_AT` → WARN. Selalu cetak `INFO step N: ~<t> tokens`.

### Task 3: `check_commits.py`, pemeriksa hasil eksekusi

Dipakai di `/mandor verify` sebelum compile/test/device. Script mengerjakan bagian deterministik; Claude mengerjakan penilaian semantik dan device.

**Files:**
- Create: `skills/mandor/scripts/check_commits.py`
- Test: `tests/test_check_commits.py`

**Interfaces:**
- Consumes: `read_meta`, `parse_step`, `apply_blocks`, `git_show`; `tests/helpers.py`.
- Produces: CLI `python3 check_commits.py <plan-dir> [--repo <path>]` (default `--repo` = cwd). Format output dan exit code sama dengan `check_plan.py`. Untuk FAIL karena isi menyimpang, cetak maksimal 20 baris unified diff (expected vs actual) setelah baris FAIL, diawali `    `.

**Aturan cek:**
1. `realpath(--repo)` ≠ `realpath(meta.repo)` → FAIL `"repo mismatch"` (Claude berhenti dan konfirmasi ke user).
2. `git merge-base --is-ancestor base HEAD` gagal → FAIL `"base is not an ancestor of HEAD (rebase/merge/reset?)"`, stop.
3. Commit = `git rev-list --reverse base..HEAD`. Ada merge commit → FAIL. Jumlah ≠ `steps` → FAIL dengan kedua angka.
4. Commit ke-i ↔ step-i (urutan). `git diff-tree -r --no-commit-id --name-status -M <sha>`: file di luar `FILES TO CHANGE` → FAIL `"out-of-scope file"`; file di daftar tapi tidak berubah → FAIL `"planned file not changed"`; aksi beda (mis. CREATE tapi status `M`) → WARN.
5. Isi: untuk tiap file di step, `expected = apply_blocks(isi di parent commit, blok step)`; actual = isi di commit. Sama → OK. Beda hanya karena whitespace (normalisasi: CRLF→LF, `rstrip` tiap baris, buang newline akhir) → WARN `"formatting differs from plan"`. Beda lain → FAIL `"content deviates from plan"` + diff. Anchor tidak bisa diterapkan ke parent → FAIL `"plan cannot be applied to parent commit"`.
6. Untuk FAIL deviasi, tambahkan baris FAIL untuk tiap baris tambahan di actual (yang tidak ada di expected) yang cocok `@Ignore|@Disabled|\bTODO\b|FIXME|NotImplementedError|!!`, dan tiap baris yang hilang di file test (`/test/` atau `/androidTest/` di path) yang memuat `@Test|assert`.
7. `git status --porcelain` tidak kosong → WARN `"uncommitted changes in working tree"`.

- [ ] **Step 1: Tulis test yang gagal**:
  - `test_exact_execution_passes` (2 step, 2 commit persis sesuai plan) → PASS
  - `test_commit_count_mismatch_fails` (1 commit untuk 2 step)
  - `test_out_of_scope_file_fails`
  - `test_planned_file_untouched_fails`
  - `test_content_deviation_fails_with_diff` (output memuat `content deviates` dan baris diff `-`/`+`)
  - `test_whitespace_only_warns` (CRLF + trailing space) → exit 0 dengan WARN
  - `test_cheat_ignore_flagged` (menambah `@Ignore`) dan `test_removed_assert_flagged`
  - `test_base_not_ancestor_fails` (repo di-reset ke cabang lain sehingga base bukan ancestor)
  - `test_merge_commit_fails`
  - `test_repo_mismatch_fails`
  - `test_dirty_tree_warns`
- [ ] **Step 2: Jalankan** `python3 -m unittest tests.test_check_commits -v`. Expected: FAIL.
- [ ] **Step 3: Implementasi `check_commits.py`.** Semua git lewat `subprocess.run([...], capture_output=True, text=True, encoding="utf-8")`, tanpa `shell=True`; diff pakai `difflib.unified_diff`.

### Task 4: `guard.py`, hook penjaga selama skill aktif

**Files:**
- Create: `skills/mandor/scripts/guard.py`
- Test: `tests/test_guard.py`

**Interfaces:**
- Produces: hook `PreToolUse`. Membaca JSON dari stdin (`tool_name`, `tool_input`, `cwd`). Exit 0 = izinkan; exit 2 + pesan di stderr (bahasa Indonesia, diawali `mandor:`) = blokir. Input JSON rusak → exit 0 (jangan mengunci sesi).
- Produces: `is_blocked(payload: dict) -> str | None` (alasan blokir atau None), dipakai test.

**Aturan:**
- `Edit`, `Write`, `MultiEdit`, `NotebookEdit`: root repo = `git -C <cwd> rev-parse --show-toplevel` (bukan repo → izinkan). `file_path` (resolve, relatif ke cwd kalau relatif) di dalam root repo → blokir: `"mandor: Claude tidak boleh menulis file di repo project. Tulis plan ke folder plan di luar repo."`
- `Bash`: blokir kalau command memuat subcommand git yang mengubah state. Regex (case-sensitive) dijalankan per segmen hasil split `&&`, `||`, `;`, `|`, newline: `^\s*(?:\S+=\S+\s+)*git(?:\s+-(?:C|c)\s+\S+|\s+--\S+)*\s+(commit|push|reset|checkout|switch|rebase|merge|stash|add|rm|mv|restore|clean|cherry-pick|revert|am|apply|tag|pull|branch\s+-[dDmMfc]|worktree)\b` → `"mandor: operasi git yang mengubah state dikerjakan user, bukan Claude."`
- Selain itu izinkan.
